# Quantum Minesweeper：審査員に説明できるまでの日本語ガイド

## 1. まず「010と101は、どちらも違う・違う」から

左・中央・右に3つの数字を並べます。

| 並び | 左と中央 | 中央と右 | 比較結果 |
|---|---|---|---|
| 000 | 同じ | 同じ | 00 |
| 111 | 同じ | 同じ | 00 |
| 010 | 違う | 違う | 11 |
| 101 | 違う | 違う | 11 |

ここで「同じ」を0、「違う」を1と書きました。**比較結果11だけを見ても、元が010なのか101なのかは分かりません。** その分からなさが役立ちます。

量子では「010の成分と101の成分が、両方ある状態」を扱います。たとえば `α|010⟩ + β|101⟩` です。αとβはそれぞれの成分につく係数で、測ったときの確率は大きさの2乗です。係数にはマイナスやiも入り、その違いが後の干渉に影響します。

データを直接測って010か101かを知ると、両者の重ね合わせを壊してしまいます。一方、両者に共通する「比較結果11」を測るだけなら、どちらの成分かを区別しません。αとβの関係を保ったまま、中央の誤りを見つけられます。

## 2. この説明の量子ビットの名前

Level 1–3のデータは `d0=左`、`d1=中央`、`d2=右`。比較結果を置く補助の量子ビットが `a0`、`a1` です。この補助ビットを**アンシラ**と呼びます。5個とも最初は0です。

説明の `|010⟩` は左からd0、d1、d2の順です。プログラムの図も上からd0、d1、d2、a0、a1です。ただしQiskitの状態ベクトルの文字列は逆順で、測定文字列も高い番号から表示します。結果の読み替えは後で具体的に確認します。

## 3. 使うゲートを、ひとつずつ

「ゲート」は量子ビットに作用する操作です。

| ゲート | どこに作用する？ | 簡単な入力で何が起きる？ |
|---|---|---|
| X | 1個 | 0を1に、1を0にする |
| H | 1個 | 0を `(0+1)/√2` に、1を `(0−1)/√2` にする |
| Z | 1個 | 0の係数はそのまま、1の係数だけマイナスにする |
| S | 1個 | 1の係数にiをかける。Hの後に使うと `+i` を作れる |
| S† | 1個 | Sを取り消す。1の係数に−iをかける |
| Y | 1個 | `Y\|0⟩=i\|1⟩`、`Y\|1⟩=−i\|0⟩` |
| CNOT | 制御1個、標的1個 | 制御が1の成分だけ、標的にXをかける |
| CCX | 制御2個、標的1個 | 両方の制御が1の成分だけ、標的にXをかける |
| 測定 | 測る量子ビット | 0か1の古典的な結果を得る |

Hで作る `(0+1)/√2` を `|+⟩`、`(0−1)/√2` を `|−⟩` と呼びます。表の0と1は量子状態なので、厳密にはそれぞれ `|0⟩`、`|1⟩` です。

CNOTは「制御を読んでから手で標的を変える操作」ではありません。測定せず、両方の成分に一貫して作用します。たとえば `|+⟩|0⟩` にCNOTをかけると、`(|00⟩+|11⟩)/√2` になります。独立したコピーが2個できたのではなく、互いに結びついた重ね合わせができています。

## 4. アンシラに「同じ・違う」を書く

最初にa0を0にします。次にCNOTを2回使います。

1. d0を制御、a0を標的にする。
2. d1を制御、a0を標的にする。

| d0 d1 | a0の変化 | 最後のa0 |
|---|---|---|
| 00 | 0→0→0 | 0：同じ |
| 01 | 0→0→1 | 1：違う |
| 10 | 0→1→1 | 1：違う |
| 11 | 0→1→0 | 0：同じ |

両方が1なら2回反転して0に戻ります。この結果が「パリティ」です。ここでは「2個の数字が同じか違うか」と理解すれば十分です。

a1にも同じ方法で、d1とd2を比較した結果を入れます。d0、d1、d2自体は標的にしていないので、CNOTでその0/1の並びは書き換えません。

中央にX誤りが起きた状態では、検査は次のように作用します。

`(α|010⟩ + β|101⟩)|00⟩ → (α|010⟩ + β|101⟩)|11⟩`

アンシラ側にはどちらの成分でも11が入るので、最後の状態を「データの重ね合わせ × アンシラ11」と分けて書けます。アンシラを読むと必ず11です。データが010か101かという情報は得ません。これが、この条件で測定しても重ね合わせが保たれる理由です。

一般の状態で何を測っても安全という意味ではありません。今回は、同じ誤りを受けた2つの論理成分が、同じ検査結果を持つように符号を設計しています。

## 5. Level 1：中央のX誤りを、最初から最後まで

最初の情報を `|ψ⟩=α|0⟩+β|1⟩` とします。

| 段階 | データの状態 | アンシラ |
|---|---|---|
| 準備 | `α\|000⟩+β\|100⟩` | 00 |
| 符号化：d0→d1、d0→d2にCNOT | `α\|000⟩+β\|111⟩` | 00 |
| 試験係がd1にXを入れる | `α\|010⟩+β\|101⟩` | 00 |
| 比較結果をアンシラに書く | `α\|010⟩+β\|101⟩` | 11 |
| アンシラを測る | 同じ重ね合わせ | 測定結果11 |
| 訂正係がd1にX | `α\|000⟩+β\|111⟩` | 11 |
| 復号：d0→d2、d0→d1にCNOT | `(α\|0⟩+β\|1⟩)\|00⟩` | 11 |

「符号化」は1個の情報を3個に広げて守ること、「復号」は元の1個に戻すことです。復号した後、元の状態はd0にあります。d1とd2は0に戻り、アンシラは誤りの記録を保持します。

訂正係が使う表はこれだけです。

| 比較結果 (左–中央, 中央–右) | 分かること | 訂正 |
|---|---|---|
| 00 | 誤りなし | 何もしない |
| 10 | 左の誤り | d0にX |
| 11 | 中央の誤り | d1にX |
| 01 | 右の誤り | d2にX |

試験係だけが入れた誤りを知っています。訂正係の関数には、その場所も、αやβも、入力状態の名前も渡していません。

実演では `α=1/√2`、`β=i/√2` の `|+i⟩` を使います。復元の途中のiが最後まで正しく残ることも確認できます。

```bash
.venv/bin/python -m minesweeper demo --level 1 --input +i --error X --location 1 --shots 512
```

実際の理想シミュレーション結果は `{'000 11': 512}` でした。最後の `11` が比較結果です。前の `000` は、復元後に準備の逆操作をしてデータ3個が0に戻ったことを表します。

## 6. Level 2の前に：Hで「＋と−」を区別する

1個の量子ビットだけ考えます。

`|+⟩=(|0⟩+|1⟩)/√2` と `|−⟩=(|0⟩−|1⟩)/√2` を、そのまま0/1で測ると、両方とも半々です。この測り方ではマイナスの違いが見えません。

そこでHをかけます。

`H|+⟩ = (H|0⟩+H|1⟩)/√2 = ((|0⟩+|1⟩)+(|0⟩−|1⟩))/2 = |0⟩`

`H|−⟩ = (H|0⟩−H|1⟩)/√2 = ((|0⟩+|1⟩)−(|0⟩−|1⟩))/2 = |1⟩`

足し合わせたとき、片方の成分が打ち消されます。これが**干渉**です。Hの後なら、＋は必ず0、−は必ず1になります。

Zは `|+⟩` を `|−⟩` に、`|−⟩` を `|+⟩` に変えます。つまり、＋/−を使う世界ではZが入れ替え誤りとして見えます。

## 7. Level 2：Hで見方を変えて、同じ訂正回路へ

3個での符号化は、まずLevel 1と同じです。その後、**3個すべて**にHをかけます。

`α|000⟩+β|111⟩ → α|+++⟩+β|−−−⟩`

**この時点でZ誤りを注入します。** 中央なら、`+++`の成分は`+−+`になり、`−−−`の成分は`−+−`になります。

次に3個すべてにもう一度Hをかけます。

`α|+−+⟩+β|−+−⟩ → α|010⟩+β|101⟩`

さっきと同じ状態になりました。あとは比較結果11を得て、**今の0/1の基底でd1にX**をかけ、復号します。元のαとβを持つ1個の状態に戻ります。

Hで挟むとZがXとして働くことを、`HZH=X` と書きます。Hを2回かけると元に戻るので、誤りがないケースも正しく戻ります。

| 境界 | ここで行う操作 |
|---|---|
| 符号化 | 繰り返し符号化→データ全員にH |
| 誤り注入点 | この＋/−の基底でZを入れる |
| 訂正の基底 | データ全員にHで戻し、0/1で検査してX訂正 |
| 元の情報を確認する点 | 復号後のd0。準備の逆操作より前 |

```bash
.venv/bin/python -m minesweeper demo --level 2 --input +i --error Z --location 1 --shots 512
```

## 8. Level 3：Yは、並びと符号の両方を変える

Yは `Y|0⟩=i|1⟩`、`Y|1⟩=−i|0⟩` です。中央にYを入れると、

`α|000⟩+β|111⟩ → iα|010⟩−iβ|101⟩`

並びは010と101なので、比較結果はやはり11です。比較結果は係数のプラス・マイナスを読まず、同じ・違うだけを調べます。

今回は「入った誤りはYだけ」という約束があります。だから場所が分かったら、その場所にYをかけます。Yを2回かけると元に戻るため、並びだけでなく係数も正しく戻ります。

ここでXだけかけてしまうと、

`iα|010⟩−iβ|101⟩ → i(α|000⟩−β|111⟩)`

となります。全体のiは観測に影響しませんが、βについたマイナスは相対的な違いなので、無視できません。復号後も `α|0⟩−β|1⟩` です。

入力を＋にすると、Xだけの訂正では−が出ます。0/1で測る割合は両方とも半々ですが、元の状態との忠実度は0です。正しくYで訂正すると忠実度は1です。この比較は実際にテスト・実行済みです。

```bash
.venv/bin/python -m minesweeper demo --level 3 --input + --error Y --location 1 --shots 512
```

## 9. Level 4：場所ではなく、種類を当てる

今度のデータは4個です。守るための2つの状態を選びます。添字Lは「符号化した論理状態」という印です。

`|0L⟩=(|0000⟩+|1111⟩)/√2`

`|1L⟩=(|0011⟩+|1100⟩)/√2`

入力 `α|0⟩+β|1⟩` を `α|0L⟩+β|1L⟩` にします。最初の入力はd0、残りは0です。符号化の操作は順にCNOT(d0→d1)、H(d2)、CNOT(d2→d0)、CNOT(d2→d1)、CNOT(d2→d3)です。

検査は2種類です。

**ZZZZ検査：** 4個のデータそれぞれからa0へCNOTします。1の個数が偶数なら0、奇数なら1になります。上の4つの並びはすべて偶数なので、正常なら0です。XかYが1個起きると1の個数の偶奇が変わり、1になります。Zは並びを変えないので、この検査だけでは見えません。

**XXXX検査：** a1にHをかけ、a1を制御として4個のデータにCNOTし、最後にa1へHをかけます。この検査では「4個すべてにXをかけたとき、状態が同じか、全体のマイナスになるか」を読みます。正常な符号語は、0000と1111が入れ替わっても同じ、0011と1100が入れ替わっても同じなので0です。ZかYが1個起きると1になります。

このように正常な符号語をそのまま保つ検査を、ここでは**スタビライザー**と呼びます。結果の0は符号＋1、1は符号−1に対応します。

| 誤り | ZZZZの結果 | XXXXの結果 | アンシラのビット (s0,s1) |
|---|---|---|---|
| なし | ＋1 | ＋1 | 00 |
| X | −1 | ＋1 | 10 |
| Z | ＋1 | −1 | 01 |
| Y | −1 | −1 | 11 |

XはZ検査と相性が悪く、ZはX検査と相性が悪い、と最初は覚えても構いません。正確には、同じ量子ビット上でXZとZXの順序を入れ替えると符号が反転します。この性質を「反交換」といいます。Yは両方の検査と反交換します。

どの位置に1個入っても、2つの検査で変わる符号は誤りの種類だけで決まります。だから、αやβを知らずに分類できます。同じ種類で場所が違う場合は同じ結果なので、**この2ビットだけでは場所は分かりません。** Level 4で要求されるのはここまでです。

読み取るのはa0とa1だけで、データ4個は直接測りません。理想シミュレーションでは、検査前の「誤りを受けた符号化状態」と、検査後のデータの状態が一致することも確認しています。誤りを取り除いたという意味ではありません。

## 10. なぜ6種類のテストで量子情報を確かめられる？

0と1だけでは、相対位相の失敗を見逃します。そこで＋、−、＋i、−iも使います。状態の0/1成分と、その間の実数・虚数の関係を調べる代表的な6状態です。

さらに「この6個で成功したから、それ以外も何となく大丈夫」とはしません。各誤りについて、論理0と論理1が**同じ全体位相**で元に戻ることを、数式と追加テストで確認します。量子操作は重ね合わせにも同じように作用するので、αとβが任意でも、その関係が保たれます。

状態忠実度は「元の状態とどれだけ一致するか」を表し、完全に同じなら1、直交する別の状態なら0です。計算機で状態ベクトルを扱える理想シミュレーションでは、直接計算できます。実機の測定ヒストグラムだけから、同じ意味の完全な状態忠実度が分かるわけではありません。

Levels 1–3のショット検証では、元の準備をUとすると、訂正・復号後に逆操作U†をかけます。元の状態に戻っていれば必ず0になります。残りのデータ2個も0に戻ったか確認します。アンシラが期待どおりで、データが000に戻ったショットを成功として数えます。失敗ショットを捨てる処理はしていません。

## 11. 審査員から聞かれそうなこと

**「アンシラを測るのに、なぜ情報が壊れない？」** 同じ誤りを受けた論理0と論理1が同じシンドロームを持ち、測定が両者を区別しないからです。中央Xの例なら、010も101も11を返します。

**「3個あればどんな誤りでも直る？」** 直りません。Levels 1–3は誤りの種類が事前に決まっています。Level 3で種類を知らずに同じシンドロームだけ受け取っても、XとYのどちらで直すべきかは決まりません。

**「Level 4は訂正している？」** 種類の分類だけです。誤りのあるデータの状態を検査中に保ち、誤り自体は残しています。

**「コードが答えを知っているだけでは？」** 誤りを入れる試験係と訂正係を別にしました。訂正係はレベルとシンドロームしか受け取りません。入力ラベルは準備と検証にしか使いません。

**「実機でも100%？」** まだIQM実機では実行していません。100%は理想シミュレーションの結果です。公式模擬バックエンドの例示的なノイズモデルでは別の成功率が出ていますが、それも実機結果ではありません。

## 最初のコマンド・実行済み検証・提出まで

ZIPを展開し、`quantum-minesweeper`フォルダで最初に実行するコマンドは `bash scripts/setup.sh` です。

実行済み：pytest 300件がすべて成功。全150ケースを各512ショット、計76,800ショットで検証し、理想状態忠実度は数値誤差の範囲で1、全ケースのショット成功率は100%でした。結果は `results/` にあります。

IQM実機で検証した内容：**Not run on IQM hardware.** 実機の認証情報と接続先が利用できませんでした。公式模擬ターゲットへのコンパイルと、その正確な変換後回路の理想シミュレーションは実行済みです。
